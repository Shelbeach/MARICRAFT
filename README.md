# MARICRAFT

Девять уровней, три локации и три босса. Godot 4.7.2 Standard / GDScript / Compatibility.

## Запуск на сервере

Нужны Linux, Git, Docker Engine с Docker Compose и доступ в интернет при первой сборке.
Замените `URL_РЕПОЗИТОРИЯ` адресом, который передал владелец проекта:

```bash
git clone --depth 1 "URL_РЕПОЗИТОРИЯ" MARICRAFT
cd MARICRAFT
docker compose up -d --build
```

На самом компьютере с Docker откройте `http://localhost:8080/`.
Godot на сервере не нужен: образ включает готовый актуальный Web release из `deploy/web/`.
F1 и режим бога в этой версии недоступны.

**Для удалённого сервера:** Godot 4.7.2 требует HTTPS; обычный `http://IP:8080/`
возвращает файлы, но браузер блокирует запуск игры. Выберите один из двух способов ниже.

### Если домена пока нет

На своём компьютере откройте терминал и создайте SSH-туннель к серверу:

```bash
ssh -N -L 8080:127.0.0.1:8080 ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_СЕРВЕРА
```

Оставьте терминал открытым и играйте через `http://localhost:8080/` в своём браузере.
Если локальный порт занят, замените первое `8080` на `8090` и откройте `http://localhost:8090/`.
Это подключение к уже запущенному контейнеру; Godot и экспорт на сервере не требуются.

### Если есть домен

Направьте DNS домена на сервер и откройте входящие TCP-порты 80 и 443.
Скопируйте `.env.example` в `.env`; раскомментируйте и заполните две строки:

```dotenv
COMPOSE_FILE=compose.yaml:compose.https.yaml
MARICRAFT_DOMAIN=ваш-домен.ru
```

Затем выполните ту же команду:

```bash
docker compose up -d --build
```

Откройте `https://ваш-домен.ru/`. Дополнительный контейнер Caddy получает и продлевает
сертификат автоматически; вручную устанавливать веб-сервер или сертификат не нужно.
Если на сервере уже есть HTTPS reverse proxy, достаточно направить его на `127.0.0.1:8080`
и использовать базовый `compose.yaml`.

Другой порт, например 8090:

```bash
MARICRAFT_PORT=8090 docker compose up -d --build
```

Проверка и остановка:

```bash
docker compose ps
docker compose logs --tail=50
docker compose down
```

Изменённый порт указывайте при последующих запусках либо сохраните `MARICRAFT_PORT=8090` в локальном `.env`.
Сохранения находятся в браузере игрока. Смена адреса, протокола или порта создаёт другой профиль.

## Как играть

«Новая игра» → выбрать героя → «Подтвердить выбор» → «Продолжить».
A/D — ходьба, пробел — прыжок, E — магия, S/стрелка вниз — труба, Esc — пауза.
Выбор любого уровня открывается после завершения кампании.

## Отдельная Windows-версия для преподавателя

Архив `MARICRAFT_Windows_x64_GodMode.zip` передаётся отдельно и не входит в Git/Docker.
Извлеките его целиком и запустите `MARICRAFT.exe`; файл `MARICRAFT.pck` оставьте рядом.
F1 → «Начать тестовую сессию» → «Заново · 1-1» → F1 → «Бесконечные сердца» и «Неуязвимость».
После перехода на другой уровень включите эти флаги заново. Подробности — в README.txt внутри ZIP.

## Исходники и повторная сборка

Откройте корневой `project.godot` в Godot **4.7.2 Standard**, нажмите F5; остановка — F8.
На рабочем компьютере владельца это `D:/Projects/MARICRAFT/project.godot`.
Нужны соответствующие export templates 4.7.2: Web release и Windows x64 debug.
Сцены — `scenes/`, код — `scripts/`, принятые ресурсы — `assets/`.

Для обновления обоих комплектов на Windows (Godot и Python 3.11+ установлены):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_handoff.ps1 -Godot "D:/path/to/Godot.exe"
```

Скрипт заново экспортирует игру, обновляет `deploy/web/`, проверяет размер файлов и собирает ZIP в
`handoff/teacher-2026-11-10/`. Эти действия нужны разработчику только после изменения игры;
преподавателю для запуска сервера достаточно одной команды Compose выше.
В Git следует передавать исходники и свежий `deploy/web/` вместе. Git LFS и загрузка ассетов с внешних дисков не нужны.
